## 2. 认证与会话
- `user`：本地密码 bcrypt（强度入 settings）+ OIDC（P4.1 尾置）。`[新增·首审三.1]` **OIDC 协议义务**：issuer 以配置并验证的**确切 issuer identifier** 精确匹配（"域名根"表述作废，O9 只是其命名来源）；audience/client_id 校验；`state`+`nonce`；**PKCE 强制**；redirect URI 精确白名单（禁前缀/通配）；JIT Team 映射失败=**拒绝登录**（禁静默入默认 Team）。
- **会话（D-IG-1 裁决采纳）**：服务端可撤销会话表；token=**CSPRNG ≥256bit**，服务端仅存哈希（高熵随机+哈希存储已足抗暴猜，无需 HMAC 无状态体系）；非秘密 session ID 定位；撤销三档（单会话/用户全部/全局紧急）；绝对 TTL+闲置 TTL；状态枚举 `active/revoked/expired`；创建/撤销/过期均 Class A 事件。
- `[新增·首审三.CSRF]` **SameSite=Lax 不替代 CSRF 防线**：cookie 携带凭据的写操作必须过 CSRF token 或等效 Origin 严格校验（既有 Origin/Host 钉 [固化] 为底线非终点）；**API 与 UI 共用授权谓词≠共用来源安全假设**。
- `[澄清·P0-1 拆表连带]` 密码 **salt 非秘密**（存库合法，不赋秘密生命周期）；pepper 可选、若用归 KMS 类；session 仅存高熵 token 哈希（无独立"哈希盐"问题）；capability 完整性材料**默认不存在**（spine 内行为受链与格网保护，不额外发明签名）。

**5.2 签署操作授权绑定（P0-4）**：capability 不是抽象的 `anchor.sign`，而是 **`anchor.sign.request`**——授权绑定到**具体签名请求**：`(request_id, root_digest, algorithm_id, serializer_id, 来源 actor, scope, expires_at, 重放规则, 重复签署规则)`；**持通用签名权而签他root 在本模型下不可能**（请求即授权对象）。规则：request_id 由 spine Class A 请求事件生成；**同 request 幂等**（重复调用返回同一签名结果，不重签）；重签=新请求（新 request_id+原因 supersedes 链，DC §3.3）；签名结果以摘要回绑请求行。
**5.3 签名请求状态机（D-IG-2 闭环；v0.2.1 补节点侧恢复契约）**：`REQUESTED → SIGNED → RECORDED`——签名是**外部副作用**，与 spine 事务天然不原子，故：REQUESTED=本地事务内 Class A 事件+状态行（原子）；SIGNED=节点产出结果+本地按 request_id **幂等落结果事件**（崩溃于 SIGNED 未 RECORDED ⇒ 对账按 request_id 取回结果，**不重签**）；RECORDED=**spine 持久化 receipt 的事件**，状态机到此终止。禁止"先记成功再签名"（虚假记录）与"签完再记请求"（孤儿签名）。
**`[补·v0.2.1]` 对账成立的前提=节点持久化幂等四保证**（最小跨域契约冻结于此；密码学协议形态归 O11 决定件）：① 节点请求账本 **UNIQUE(request_id)**，含请求摘要+结果，**禁仅进程内缓存**；② 同 request_id 携不同 root_digest/algorithm_id=**拒绝不覆盖**；③ receipt 可验证对应 (request_id, 请求摘要)——不得仅凭结果文件认定已签（验证形式=O11 决定件必含项）；④ 账本保留至 spine RECORDED 确认后且覆盖审计保留期，节点重启可恢复；⑤ **（v0.2.2）节点支持对 request_id 的可验证取消/失效 fencing**——已作废请求即使延迟到达亦不得执行；fencing 协议形态=O11 决定件必含项。对账失败路径（v0.2.2/P0-4 收口）：**超时只能证明"调用方未按期取得结果"，不能证明节点未执行外部副作用**——禁止仅凭本地超时创建可执行替代请求。超时后先查节点持久账本，按四分支处置：**已签名**→取回原 receipt→RECORDED；**处理中**→保留原 request_id 继续对账；**未受理**→关闭旧请求→supersedes 新请求；**UNKNOWN（节点不可达等）**→保持待对账，**不签发替代请求**。替代旧请求的前提=取得节点侧可验证的取消/失效确认（保证⑤ 的 fencing）——"spine 已关闭"不构成节点停止执行的证明。本模型追求**可恢复的幂等执行+对 UNKNOWN 的保守处理**，不承诺原子 exactly-once。**RECORDED≠锚定发布**：对外发布为锚定对象的独立 Class A 事件流（DC §3.4），失败恢复按 (root_digest, algorithm_id) 幂等重试——"签名完成但锚定未发布"是合法中间态（§8 已定其交付语义），两恢复路径不混。
**5.4 O11 记录（D-IG-2 裁决，待治理主体批准）**：**B（组织 KMS/HSM）=生产锚定优先方案**；**A（同机隔离容器）=受限部署**——仅当 AM §4c 六项独立验证全 PASS 且宿主 root 威胁边界在声明中明示后方可用，**不得包装为抵御宿主失陷**（六项：spine 不可读私钥/不可直调私钥文件/容器无 docker.sock/无共享宿主权限旁路/节点独立授权与审计/宿主 root 边界声明）；**C（独立用户态进程+age）=仅过渡，禁入生产锚定**。

## 6. 撤销模型（P0-2 重写：I4 的唯一定义）
| 主体/对象 | 撤销生效要求 |
|---|---|
| user session | 下一次受保护请求即拒 |
| capability grant | 下一次授权判定即拒 |
| agent_run | 规定写入/敏感操作执行点重新核验（run fence [固化] 基础上 G-B 补构建维） |
| service_principal | **下一次受保护调用即拒**（v0.1"允许一个调用窗口"表述作废） |
| 在飞长任务 | 在**定义的执行检查点**重新验证（检查点集合=每次 provider 授权、每次 spine 写 verb、每次签名/交付请求），不得无限延续 |
- **决策点零缓存（v0.2.1 方案 A——30 秒窗从撤销语义中移除，I4 无条件成立）**：`allow/deny/require-signoff` 判定的输入**只允许实时 spine 读**；mc per-invocation 进程模型 [固化] 天然如此，本条将其冻结为义务：**任何缓存/衍生状态不得进入判定输入**。若未来引入进程内缓存，必须带 **epoch fence**：撤销事件在同一写事务（DC §3.2）bump 相关 actor/grant 的 epoch，缓存项以 epoch 为键成分，跨 fence=失效。≤30s 陈旧窗仅允许存在于**渲染/聚合读与"只可能拒绝、不可能放行"的候选预筛**——它们不是权限来源。上表"下一次即拒"因此无例外；在飞长任务的"检查点"=其每一次写 verb/签名请求/交付请求（全部实时 spine 读；provider 侧 per-request liveness [固化] 为既有先例）。
- `[新增]` **派生 grant 随 granter 失效即失效**（不等原 TTL）：比较基准=granter 撤销事件的 **effective_at**（recorded_at 仅审计用，DC §3.3 规则复用）；撤销事件与 grant 状态行翻转变更**同一写事务**提交（DC §3.2）。

## 7. 存量迁移（P0-3 重写：归因保护）
- **历史 Actor 不改写**：历史事件中的 `'operator'` 保留为**遗留主体**（登记为 `legacy:operator` actor，语义="部署期单操作员上下文"），任何迁移**不得**把其原始 actor 字段改写为具名 user——**权限承接 ≠ 历史行为归因**。
- 部署所有者以**新建 user actor** 出生；其"承接旧 operator 管理权限"通过迁移事件（Class A：对具体 capability 集的显式授予）表达。
- 关联以 `legacy_actor_mapping`（映射表本身 Class A：`legacy:operator → user_X, 依据=部署记录, 性质=权限承接, 强度=不推定行为同一`）；**更强的历史归因（"就是同一人执行"）仅在有独立证据时按映射行的证据字段追加**，默认禁。
- 审计含义（DC 侧）：验证器与离线审计读到的历史链**逐字不变**，迁移只增事件不改旧行——DC §3.2 原子审计与本条互验（A5 相应更新）。
- `[补·v0.2.1]` **封存规则**：迁移完成后 `legacy:operator` 即封存——新写入在 guard 与 trigger 双点拒绝（[固化]格网承载），**无默认兼容路径**；任何保留例外须显式 grant 并限期；验收扩展并入 IG-T5（防"历史保护完成而旧身份继续写入"的混合态）。

## 8. 失败语义
（v0.1 基础上 D-IG-5 收紧）：签名节点不可达 ⇒ **不阻塞生产执行及其不依赖签名的后续工作**；签名请求入 §5.3 可恢复队列；**凡以签名/锚定为交付接受条件的对象保持待完成，不得提前进入 `Delivery Accepted`**；禁跳过/伪造成功/人工改状态放行；恢复后按 request_id 幂等补齐。**治理拒绝权不越界为无边界停摆权；生产自治不豁免交付完整性条件**（Autonomy Preservation 两面）。
