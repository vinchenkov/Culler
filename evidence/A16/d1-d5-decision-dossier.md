# A16 D-1..D-5 决策档案（供所有者一次裁定；执行侧不自行定安全参数）

依据：003 附一"参数与 enforcement 定案前资源维保持 GAP"；TM §5.2:94/99、RR-7:171；目标机 O3 卡事实（ext4 未挂 prjquota、docker=overlayfs/containerd、503G RAM、53G 磁盘可用）。逐分叉列**选项·约束·爆炸半径·建议**，数值批准权与门放开权归所有者。

## D-1 磁盘配额机制（最难，环境依赖；无"免费且完整"选项）
| 方案 | 覆盖 TM:99 作用域（工作区/临时/日志/宿主共享卷） | 需宿主改造 | ENOSPC 语义 | 主要代价 |
|---|---|---|---|---|
| a) ext4 project quota | **全覆盖**（真配额、写失败） | **是**：mkfs project 特性 + `prjquota` 挂载选项 + root 配置，且需与 spine 卷分项目 | 真 ENOSPC | 越出"部署不升权限"，属**宿主 provisioning 契约**（非部署动作）|
| b) tmpfs 化短生命周期目录 | 部分：临时/scratch/日志容器侧（**工作区=仓库 bind，不能 tmpfs**） | 否 | 真 ENOSPC | 吃宿主 RAM，与容器 mem 此消彼长 |
| c) 度量看门狗 + 预检 df | 观测+提前终止，**非写失败** | 否 | 假（终止代替） | TM:99 要"写失败且资源类终态"，c 只兑现后半 |
| d) xfs 专用 backstore（loop/独立盘 + pquota）给工作区卷 | 全覆盖真配额 | 是：新增专用挂载/回环设备，部署拓扑变更 | 真 ENOSPC | 引入部署存储前置，运维复杂度高 |

- **执行侧建议（非裁定）**：**b + c 组合**为部署内自洽基线——临时/日志/scratch tmpfs 上限（真 ENOSPC）+ 工作区**看门狗**周期 du 越软限即提前以资源类终态终止 run（现有 `update_checkpoint.go:616` df 预检、`project-cache` 字节会计可复用）；**工作区灌满宿主共享 FS 这一维 b/c 不闭合**，需 a 或 d，属宿主契约决策。
- **需所有者定**：①是否接受 b+c 作为本票闭合集、把"工作区真配额"登记为**宿主契约/F0a 残余**（爆炸半径=宿主 FS，明示不藏）；②还是要求实现 a/d（则须先给宿主 provisioning 授权）。**"配置即拒启动"式硬门（无配额不许起 T2）我倾向保留为开关**，是否默认开归 D-5。

## D-2 fd / NOFILE（无分叉，仅数值）
- 机制：agent/collie 容器加 `--ulimit nofile=SOFT:HARD`（全 docker 环境通用，无 FS 依赖）。现状：mc/resident/runner **零 ulimit**，fd 继承 docker daemon 默认（盘点 §6）。
- **需所有者定数值**（建议 T1=T2 同，示例）：`nofile=1048576:1048576`（大）vs 更紧的如 `65536:524288`。**机制我可直接实现，数值待批**。

## D-3 日志配额
- 现状：容器内 `runner.ndjson` 硬顶 4MiB/run 写满停+留痕 **[已固化]**；run 树计数修剪（500）**非字节**；docker `json-file` **无 max-size**（盘点 §5，宿主 VM 侧可灌满）。
- 建议：agent create 加 `--log-driver json-file --log-opt max-size=Nm --log-opt max-file=k` 封顶 docker 日志；run 树加**字节预算**（计数 500 之外）；runner.ndjson 既有 4MiB 保持（改它即破坏 [固化]，非放宽）。
- **需所有者定**：max-size/max-file 值、run 树字节预算上限。

## D-4 T1/T2 强制参数表数值（TM 刻意留白，纯所有者）
- 待填每维 {cpu, mem, disk-workspace(取决于 D-1), fd, log-run, log-tree, pids(已 2048), deadline} × {T1 受审核外部, T2 不可信=默认档}。
- 执行侧可据宿主包络（503G RAM / 并发 WIP 上限）呈**建议数值草案**供逐行批改，但**不代填**——数值=可用性×成本×爆炸半径的权衡，属所有者。deadline/pids 已有（45min / 2048）。

## D-5 默认策略（行为变更面，需拍板）
- **(i) 非零默认**：未配置即用 T2 默认表 → 现网"默认不限"变"默认受限"（可能让既有大内存任务失败率上升）。
- **(ii) 配置即拒启动**：未显式配置则不可信档禁止 spawn → 最硬、零静默放开，但把默认行为从"能跑"变"不配就不跑"。
- 执行侧倾向：**(a)+(b) 混合**——T1 用 (i) 非零默认保可用，T2（不可信）叠加 (ii) 强制显式配置方可起。是否采纳、每档取哪个归所有者。

## envelope/attestation 缺口（独立于以上数值；无分叉，可直接实现）
- 盘点 §3/§9：新资源标志（ulimit/log/blkio/shm）**不进 collie-envelope digest**，等于"设了但没证"。此为纯机制补齐，不涉数值选择——待 D-2/D-3 落地时**一并实现摘要面扩展**（把新标志纳入 plan 闭包），无需单独裁定。
