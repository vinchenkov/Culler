First implementation

Support configured model providers with static keys in known request headers.

Separate compatibility work

Body credentials, signed requests, custom protocols, and account sign-in require separate support. The proxy cannot infer their authentication rules.

Separate network control

An encrypted tunnel cannot replace an encrypted authorization field. Enforced network rules prevent direct connections around the gateway.

What this fixes

A package cannot copy a real provider key from the container. The provider rejects a copied Culler gateway credential.

What remains

A valid run can still spend its allowed budget and transmit source through allowed model requests.

Simple example

A malicious package copies its environment. It finds a temporary Culler credential, not the provider key.

The concrete change

  1. Run a separate proxy under resident supervision for supported model providers. Keep their static keys in the host credential store.
  2. Give each run a temporary gateway credential. Configure the harness to use the gateway address.
  3. Permit only configured accounts, destinations, request paths, and methods. Set request and account spend limits.
  4. Configure the provider destination and exact authentication header. Other authentication protocols require separate support.
The gap this covers

A command cannot directly copy the real provider key from its environment or authentication file.

What remains possible

The run can still make allowed requests through its gateway credential. An allowed model request can still transmit source text.

The change passes when: A test key stays absent from the container. The approved provider receives it. Expired or revoked credentials and undeclared destinations fail.

Details, definitions, and source evidence

This proposal covers static application programming interface (API) keys for model requests from the agent harness.

Each supported connection defines its destination and authentication header, such as Authorization: Bearer or X-API-Key.

The proxy forwards the request body and response stream without interpreting the model request.

Database passwords, private keys, and general Project secrets remain outside this proposal.

Signed requests, custom protocols, and credentials inside a request body require separate adapters. The proxy cannot infer them.

OAuth is the account authorization protocol used by sign-in flows. Its traffic can use a gateway too.

OAuth support requires the correct request protocol and token renewal. Until those tests pass, access tokens still enter the container.

An encrypted tunnel cannot change the encrypted authorization field. Prefer an explicit gateway address where the harness supports one.

The gateway protects the key. The separate network proposal prevents direct connections around the gateway.

For a harness without gateway support, a larger change can separate its model requests from its repository tools.
