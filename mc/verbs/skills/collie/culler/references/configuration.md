# Configuration

Read the current configuration before an edit.
Use the expected configuration revision where the command requires one.
Keep provider sign-in and secret entry in the existing operator interfaces.
The agent can inspect connection state without provider credentials.
Internal credential retrieval, renewal, grants, and execution remain host component operations.

## Profiles and models

Use the live model catalog and its availability state.
An OpenCode download request can remain active; inspect its recorded operation until it completes.
A profile draft stays separate from the saved profile.
A test of an unsaved draft preserves the saved profile's verification state.
Obtain explicit authorization for provider expenditure before a model test.
Keep the test operation identifier and inspect its state after an uncertain response.
A pending test is not a verified profile.

A profile save requires evidence for the same execution configuration and credential authorization.
A changed execution configuration needs matching test evidence before activation.
Role assignment changes retain the profile validation rules.
Read the current assignments before a role assignment change.
A profile test and provider authorization are separate operations.

## Connection recovery

Inspect the connection condition before a check, retry, or cancellation.
Use the operation identifier for subsequent state reads.
A successful connection check preserves independent Project or task conditions.
The runner owns complete model response records and connection recovery reports.
The agent does not submit those internal reports.
